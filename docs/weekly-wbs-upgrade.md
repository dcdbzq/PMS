# 使用与业务规则：项目、WBS 与周报

系统采用独立 Web 应用、本地账号与 SQLite，默认不连接飞书。本文介绍项目层级、周报填报、角色权限与统计规则；通用部署与备份步骤见 [部署与数据管理](deployment.md)。

## 新建项目与子项目

公司管理员和部门负责人通过「项目空间 → 新建项目」创建项目。部门负责人只能在授权部门中新建项目。无需填写项目编号、立项编号或来源单号，项目详情与导出也不展示编号。新建时默认将创建人加入查看人；参与人可以同时保留查看人身份。旧数据库的历史字段不删除，但业务界面与导出不再使用。

项目列表默认只展示顶级项目，点击父项目名称或箭头逐级展开子项目。通过缩进、连线和图标体现层次；添加子项目后自动展开其所属层级，搜索子项目时自动展开匹配路径。

项目可以继续拆解为多级 WBS 子项目。公司管理员可管理全部项目；项目负责人可管理本节点和全部下级节点、配置人员和时间、调整状态及添加子项目，不要求自己作为参与人。部门负责人还可管理归属部门的项目并指定负责人。服务端阻止循环层级、无权限移动和归属部门越权。

项目空间可切换「我负责的」「部门项目」「我参与的」「全部可见」，入口按权限出现。部门项目包括部门承担的项目和本部门成员参与的跨部门项目；后者只展示本部门成员信息、投入和授权周报，完整资料及其他部门记录须另获项目授权。

新增稳定的「归属部门」：旧项目首次迁移按顶级项目负责人所在部门确定，子项目继承。以后负责人调岗、更换负责人不会自动转移项目归属；子项目跟随上级，调整整个分支时同步更新下级。管理员或授权部门负责人可调整归属，未分配部门的历史项目由管理员确认归属后交给部门管理。

每个节点分别配置参与人、查看人和参与起止日期：

- 参与人只在本节点填报，不会自动成为其他节点的参与人。只负责某阶段的员工，可仅加入相应子项目。
- 负责人身份与填报参与身份独立；只有勾选为参与人且处于参与时间内才能填报。已有参与关系全部保留，可在项目配置中调整。
- 普通参与人默认只读自己的周报；单独配置为查看人后，可以查看授权项目内其他人的周报。负责人可查看负责节点和下级的周报，但不会因此看到成员其他项目或非项目工作的详情。
- 参与日期留空时不额外限制参与时间，直到项目归档；项目计划截止日期逾期不会阻止继续填报。配置了参与区间时，与填报周有交集即可填报，不要求全程参加顶级项目。
- 查看人可看本节点与下级节点的周报，不能仅凭查看身份填报。查看仍受账号的「查看周报」权限控制。
- 子项目参与人可看到上级目录以理解 WBS 路径，但不会因此获得其他兄弟节点及上级周报的查看权限。
- 归档节点会关闭本节点及下级的新填报入口。原先已提交的历史项目条目仍可修改，历史记录不删除。
- 已有项目迁移为顶级节点，原有成员保留。历史条目和附件继续关联原项目。

## 按周填报

每个项目条目包含：本周工作成果、下周计划、需要协调的工作、累计开发进度、本周工作量比例，以及原有附件功能。成果和下周计划必填，协调事项无则留空。

非项目工作量位于项目填报下方，用下拉框选择「休假」「学习/研究/培训」「其他」。每类最多一条，可以组合；填写比例和工作说明。没有项目的周，也可通过非项目条目完成填报。

项目比例与全部非项目比例合计必须等于 **100%**，最小单位为 0.5%。页面禁用不满足条件的提交按钮，服务端再次校验并在一个事务内保存；校验失败不会覆盖已提交的数据。整周休假时需移除项目条目，历史项目进度继续保留。

原有休假比例和说明自动迁移为「休假」分类。历史周报缺少下周计划和协调事项时按空值保留，不虚构历史内容。旧版 API 请求可继续使用 note、leave_percent 和 leave_note；新版页面统一提交完整字段和 non_project_entries。

## 按权限呈现工作总览

普通参与人只看到本人的参与项目、本周投入、协调事项、个人周报和时间分布。不展示部门/公司统计入口及团队填报人数；个人总览不请求管理范围统计。

项目负责人、部门负责人及公司管理员登录后默认进入负责范围的总览，额外显示三个简洁的切换入口：

1. **我的工作**：与参与人相同，聚焦本人参与的工作与填报。
2. **负责项目 / 部门项目 / 公司总览**：按身份展示项目投入、部门汇总和最近进展。项目负责人另有项目配置快捷入口。完整项目统计、人员投入与更新状态、周报明细按需展开；兼任角色可切换统计范围。
3. **待办与异常**：集中查看待更新周报、协调事项、逾期项目和人员投入提示，可向单人或全部待更新人员发送站内提醒。

人员投入提示包括一周4个及以上有记录的项目，以及旧数据中已提交但总量不为100%的情况。当前填报统一要求100%，因此不将正常填报标记为超负荷；项目负责人的投入提示仅统计负责项目。该提示供工作协调参考，不增加绩效判断或周报审批流程。

提醒在接收人的工作总览中显示。已更新对应周报后不再显示该周提醒；没有连接飞书或其他消息服务。

### 协调事项的完成状态

每条项目周报中非空的协调内容算一项，数量按所选周次统计。发起人、负责范围内的项目/部门负责人及公司管理员可点击「标记完成」。完成后个人、项目、部门和公司范围内的待协调数量同步减少，事项移至「已完成的协调事项」折叠区，保留内容、处理人和完成时间。误操作可「重新打开」，数量加回。仅有项目查看或统计权限的用户不能处理其他人的事项。

修改成果、计划或工作量不改变协调完成状态；修改协调内容后重新作为待协调事项。其他周的同名协调内容是独立事项。服务端校验操作时的原内容，防止用户用旧页面完成刚被修改的请求。

公司管理员只保留公司总览和待办与异常，不显示个人工作、填报入口或个人本周投入。管理员不计入应填报和催报名单，已有的个人填报权限配置也不再使管理员成为填报人员；历史周报和投入仍保留供统计、查看和导出。

统计口径：

- 100% 表示 1 人周；多个人的项目工作量可超过 100%，不是项目完成率。
- 每个 WBS 节点分别显示「本节点投入」和「含下级投入」。总量只累加原始周报条目，不重复累加父级汇总。
- 部门统计按人员当前部门归属汇总；跨部门项目中，部门负责人仅统计授权部门成员的投入。明确授予的项目查看权限可以额外查看该项目周报，但不扩张部门统计范围。
- 应填报人员为所选周结束前已创建、当前启用且有填报权限的账号，包括没有分配项目的人员。未填报=应填报减去已提交周报；整周休假、整周培训也算已填报。
- 项目范围仅将负责项目中本周有效参与人员及本周已有项目记录的人员纳入统计；结束参与、归档后的无记录成员不再催报。已提交整周休假或培训也算已更新，不暴露具体非项目分类及说明。人员表另列是否有项目记录，避免把“已提交周报”理解为“本项目必有投入”。
- 账号停用状态、部门与权限采用当前资料，未建立历史组织快照。历史周如需按当时组织口径统计，需要另行增加组织履历。
- 开发进度继续采用当前成员各自最新累计进度的平均值；不将父级工作量或成员平均进度当成按任务权重计算的完成率。

## 权限配置

管理员在「团队成员 → 添加/编辑成员」选择角色，可分别调整填报、查看及三个统计维度的权限，并配置授权管理的部门。多个部门用顿号或逗号分隔；留空时部门统计使用本人部门。

| 默认权限 | 普通参与人 | 项目负责人 | 部门负责人 | 公司管理员 |
| --- | --- | --- | --- | --- |
| 填报本人周报、个人统计 | 是 | 是 | 是 | 否，专注管理 |
| 查看其他人周报 | 单独授权项目 | 负责项目及下级 | 本部门成员完整周报、部门承担项目 | 全公司 |
| 项目投入统计、成员更新状态及提醒 | 否 | 负责项目范围 | 部门范围，可叠加负责项目 | 全公司 |
| 项目配置、人员与WBS管理 | 否 | 负责项目及下级 | 归属部门的项目 | 全公司 |
| 新建顶级项目、指定负责人 | 否 | 否，可添加子项目 | 授权部门 | 全公司 |
| 账号、全局权限及全量导出管理 | 否 | 否 | 否 | 是 |

项目负责人由项目的负责人字段产生，无须将账号整体改成特殊角色；可以与部门负责人兼任。仅授予部门/公司统计权限不授予项目编辑或新建权限。部门负责人看到跨部门项目时，本部门人员范围外的正文、附件和完整资料仍须单独项目授权。

取消「查看周报」后，用户仍能查看本人周报，其他人的正文、非项目说明及附件均不提供；已授予的统计权限仍可查看汇总数字。单独授予公司统计权限不会授予账号管理权限。所有边界在服务端执行，隐藏页面按钮不是授权依据。

## 服务器升级

1. 停止现有服务，使用现有备份工具备份数据库与附件目录，核验备份成功。保留原代码与服务器自己的 .env。
2. 更新 app.py、**新增的 domain.py**、feishu.py、backup.py，以及整个 static/ 目录（包含 management.js、overview.js、projects.js、refinement.css）。上传发布包时不要覆盖 data/、附件目录或 .env。
3. 保持 `PMS_AUTH_MODE=local`。继续沿用服务器的数据库、附件路径、端口、反向代理和进程守护配置。
4. 启动服务时自动增加字段和表，保留已有数据，不需要重建数据库。多次启动可重复执行迁移。
5. 登录检查已有项目、历史周报、附件下载；给部门负责人配置部门及角色，再配置项目查看人和阶段参与时间。普通成员登录检查个人总览，确认不出现管理入口及团队填报指标。浏览器刷新到新版页面。
6. 如需回退，停服后恢复升级前的代码、数据库和附件备份，再启动旧服务。新版分类填报后不应直接用旧版应用继续写入数据。

示例（路径以实际服务器为准）：

```powershell
python backup.py create --db D:\pms-data\pms.sqlite3 --out D:\pms-backups\before-wbs-20261021
python backup.py verify D:\pms-backups\before-wbs-20261021
python app.py --host 127.0.0.1 --port 8080 --db D:\pms-data\pms.sqlite3
```

使用独立附件目录时，备份和启动命令均需提供对应的 `--uploads` 参数。HTTPS 部署继续设置 `PMS_SECURE_COOKIE=1`；`.env.example` 中的 0 用于本机 HTTP。

## 验证

```powershell
python -m unittest discover -s tests -v
python tests/browser_smoke.py
python tests/browser_roles.py
python tests/browser_coordination.py
```

自动测试全部使用临时数据库。新增覆盖：分类及 100% 原子校验、多级 WBS 与循环防护、查看人与附件权限、参与日期与历史修改、跨部门报告隔离、统计与正文权限分离、父子汇总不重复、站内提醒授权，以及迁移可重复执行。浏览器验收覆盖本地账号、角色配置、WBS 创建、周报字段、分类位置、附件、统计、提醒、导出和手机布局。
